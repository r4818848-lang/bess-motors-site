## Хранение кейсов

Выбрано существующее Supabase, не новый сервис. Таблица `crm_store` и публичный бакет `work-order-files` не подходят: в первом лежат клиенты, второй отдаёт файл по открытой ссылке. Черновик `supabase/drafts/seo-cases.sql` создаёт отдельные таблицы и функцию `seo_case_apply` в одной транзакции: версия строки, `for update`, ключ повтора, фото в `bytea`, журнал действий. Приложение этот SQL не запускает.

Пока нет флага `SEO_CASE_STORAGE=supabase`, запись возвращает `STORAGE_NOT_CONFIGURED`. Сбой хранилища возвращает `STORAGE_UNAVAILABLE`, а не пустой список. Sitemap при этом остаётся целым и просто не добавляет кейсы. Модуль каталога: BLOCKED.

Тесты памяти, не production: повтор запроса не создаёт второй кейс, параллельное сохранение одной версии даёт один успех и один `conflict`, сбой не стирает уже записанное, снимок переживает новый экземпляр хранилища, черновик и архив не отдают фото, публикация без подтверждения кадра запрещена, битый JPEG и SVG отклоняются, EXIF не остаётся в новом JPEG.

## Риски

- Карточка Google и часть каталогов не прочитаны официальным API. Чеклист нельзя считать уже внесённым в карточку.
- Сниппеты поиска могут ещё показывать старые часы «пн–сб 8:00–18:00», хотя текущий HTML production их не содержит.
- Каталог работ на production закрыт, пока владелец не выполнит SQL и не включит флаг. Это безопаснее, чем запись в локальный файл. Регулярное выражение не видит номер и лицо на фото: публикация требует отдельного подтверждения кадра. На DobryMechanik по-прежнему чужие часы, включая открытое воскресенье. Карточку там не меняли.
- Распознавание лиц на фото нет. Владелец сам кадрирует снимок. Код снимает EXIF и режет явные идентификаторы в тексте.
- Панель не рисует график при NO_DATA. Рекомендации подписаны отдельно от измерений и ничего не публикуют.
